# Prediction ledger: draft, not production ready

`0011_prediction_ledger` creates publications and settlement events independent of expiring operational foreign keys. The insert trigger assigns database UTC time, checks the source snapshot and rejects late publication; a deferred trigger checks the clock again at commit. Settlement events retain score, result identity, verification time, source and revision links. A database trigger checks the current matching verified result and serializes revision insertion. Ordinary update, delete and truncate are rejected by triggers; dedicated NOLOGIN reader and writer roles receive limited privileges. Database owners, superusers and administrators who can alter triggers or grant roles can bypass these protections. This is not cryptographic non-repudiation.

`publish()` and `settle_final()` are transaction-scoped internal functions, not network endpoints or schedulers. An authorized caller must invoke them at the actual publication and verified-result boundaries. **No existing live publication pipeline calls them**, and a committed record proves only the application recorded an event, not external delivery. Do not backfill legacy predictions. Existing results and cleanup jobs are unchanged. No odds are accepted or inferred until licensing, source and capture-time evidence are independently integrated. Only 1X2 is automatically scored; unsupported verified finals become UNSCORED, verified cancellation becomes VOID and postponements remain pending.

`GET /api/v1/prediction-ledger` offers bounded offset pagination (`limit` 1–100, `offset` 0–10000) and `start`, `end`, `tz` (`UTC` or `Europe/Istanbul`), `league`, `market`, `model` and `status` filters. End dates are inclusive local calendar dates and translated to an exclusive UTC boundary. Ordering is publication time and UUID descending. Offset pages can shift during concurrent publication; clients needing a stable snapshot must retry or use a future cursor implementation. The default list and `/metrics` use only the latest publication revision and latest settlement revision. `GET /prediction-ledger/{id}/events` returns up to 1000 settlement versions for audit; more requires a future paginated endpoint. `PENDING` means no settlement event. The intended verified hit rate is WON/(WON+LOST), excluding pending, void and unscored. Since independent public-delivery evidence is not implemented, counts are provisional and `sample_size` is 0 and `hit_rate` is null even when provisional events exist; `provisional_sample_size` labels their separate count. Legacy predictions and odds are excluded, and `publication_delivery_verified` is always false. Do not treat these metrics as independently verified public predictions.

The migration creates two cluster-wide roles and thus requires `CREATEROLE`; it fails if those names already exist. A DBA must review role ownership, memberships, schema CREATE rights, connection identities, backup and rollback before any production migration. No login is granted automatically. Downgrade refuses a nonempty ledger or assigned roles; removal of live evidence requires a separate backup and human procedure. Migration and changes in this PR must not be applied to production without separate authorization.

Remaining before readiness: an actual public-delivery boundary with immutable independent receipt; explicit source/normal-time verification contracts, licensed odds evidence, end-to-end wiring, independent role and trigger security review, production backup/recovery rehearsal and staging validation. No live ingestion, deployment or production migration is authorized here.

## Unrelated CI failure investigation

The verified Bundesliga batch archive test fixes `NOW` at 2026-11-27 but lets SQLite assign real `last_updated_at` and `updated_at` defaults. Once execution time is later than that fixed instant, lifecycle `available_at` is later than the test read time and match history raises `NO_AVAILABLE_REVISION`, reported as `PARTIAL`. An isolated copy reproduced the failure; assigning both fixture timestamps before the fixed instant made it pass. No production archive code or repository test was modified for this investigation. Running that test alone also needs the SQLite JSONB compiler registration that full-suite collection currently supplies.
